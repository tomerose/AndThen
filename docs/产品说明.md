## 〇、一句话

知乎沉淀了十几年的真实人生经历，但时间把它们变成了**半截故事**——读者看完就走，作者写完就停，平台只能反复推荐同一批老内容。

「然后呢？」给这批存量内容接上一条**有授权、可追溯的后续链路**：读者对一条旧回答表达"我想知道后来"，原作者自愿接受基于原文的 AI 回访，逐项确认后在本站发布「后来」。**不生产新内容，只让已有的内容长出结局。**

## 一、思路

### 1.1 问题

| 问题 | 证据 |
| --- | --- |
| 读者对"半截故事"的追续动机无处安放 | 调研 53.8% 的受访者读完旧帖还想继续了解；73.1% 认可"关注旧帖后续"的价值；而平台没有承接这个动作的产品 |
| 作者补充后续的门槛过高 | 回访意愿不是问题（4 位受访作者**无人拒绝**），负担才是——重写长文、被催促、被评判 |
| 存量长尾内容没有新的生命周期 | 没有新内容节点，长尾回答只能靠重复推荐 |

### 1.2 我们做什么 / 不做什么

**做**：在**获准展示**的历史内容上，跑通「关注后续 → 回访 → 作者确认 → 发布后来」这一条闭环。

**不做**（写进产品边界的八项决策，见企划书§4）：

- 不独立核实人生结果——"时间验证"仅指对照当时表述与后来回访，**不构成事实审计或因果证明**
- 不替作者生成未提供的结果——AI 负责识别、采访、证据关联与整理，**不虚构任何"后来"**
- 不以收入、疾病或人生输赢作为吸引点
- 不依赖全量历史数据或站内推送才能运行

### 1.3 核心闭环

```
获准展示的真实旧回答
        ↓
   读者关注后续          ← 一人一帖一票，可撤销
        ↓
   判断是否适合回访      ← 规则初筛 + 模型判定
        ↓
  人工 / 已验证渠道邀请   ← 系统不自动发任何邀请
        ↓
     核验原作者          ← 只有知乎 OAuth 能证明"本人"
        ↓
     AI 动态采访         ← 最多五问，一问一答，可跳过可暂停
        ↓
   作者逐项确认          ← 每条内容必须恰好确认一次
        ↓
   发布「后来」          ← 默认私有，公开需单独确认
        ↓
  关注读者收到更新
```

## 二、用户

采用**广度问卷 + 深度访谈**双线验证：读者侧问卷验证"需求是否存在、集中在哪类内容"；作者侧访谈验证"意愿与顾虑边界"。

### 2.1 读者侧：需求存在，且高度集中

样本：27 人提交、**26 份有效**。三类内容对照设计，每人随机阅读 5 篇并逐篇作答。

| 指标 | 结果 |
| --- | --- |
| 读完还想继续了解 | **14 人（53.8%）** |
| 认可"关注旧帖后续"功能 | 很有价值 4 人 ＋ 比较有价值 15 人 ＝ **19 人（73.1%）** |

**三类内容对照**（16 篇帖子随机分配，每人读 5 篇；**分母 = 该类帖子被读到的总次数**，不是 26 人——不是所有人都读到同一篇）

| 内容类型 | 帖子数 | 被读到 | 想知道后续 | 勾选率 |
| --- | --- | --- | --- | --- |
| **B 类 · 反差／判断型** | 6 | 52 | **9** | **17.3%** |
| **A 类 · 情绪宣泄型** | 5 | 26 | 4 | 15.4% |
| **C 类 · 知识恒久型** | 5 | 52 | 1 | 1.9% |
| 合计 | 16 | 130 | **14** | — |

单篇最高：**《43 岁辞职》——读到它的 8 人里有 3 人想知道后续（37.5%）**；《房地产最后五年》3/9 = 33.3%。另有 **8 篇为 0%**。

**三个关键发现**

1. **需求高度集中，而非普遍存在。** 16 篇内容里最高的一篇是 37.5%，**另有 8 篇为 0%**。功能不适合对所有内容开放，应精准识别**存在未完成事件、计划或判断**的内容。
2. **"感兴趣"与"想知道后续"是两件事。**《熵增定律》被 11 人读到，正面阅读感受 9 人（81.8%）**全场最高**，但**无一人想知道作者后来**。知识型内容满足当下的信息需求，不产生追续动机——直接支撑"不对信息已闭环的内容植入入口"的决策。
3. **触发追续的是叙事缺口与自我投射，不是热度。**"作者留了一个没讲完的故事"（53.8%）与"作者的经历和我自己的处境相似"（42.3%）远高于"作者很有名""文章获赞多"这类社会线索；而"都不会，我只看当下的信息"**得票为 0**。**入口筛选的依据应当是内容结构，而不是互动数据。**

### 2.2 作者侧：意愿不是问题，边界才是

样本 4 份，覆盖"发布过"3 人与"未发布过"1 人，含 1 位明确对 AI 持保留态度的受访者。

| 样本 | 是否发布过 | AI 回访意愿 | 顾虑 |
| --- | --- | --- | --- |
| 样本 1 | 没有 | 看情况而定 | 涉及隐私 |
| 样本 2 | 是，专业领域 | 非常愿意 | 涉及隐私 |
| 样本 3 | 是，个人规划 | 看情况而定 | 失败、遗憾的经历 |
| 样本 4 | 是 | 看情况而定 | 涉及隐私、对 AI 持保留态度 |

**核心观察：无人拒绝参与。**

- 接受回访的条件（多选）：可跳过不想回答的问题 **75%**、可设置公开范围／匿名／只保存不公开 **75%**、AI 能理解我表达的内容 **75%**、可自行修改 AI 整理的内容 50%、不需要重新写很长的文字 25%
- 不愿接受回访的原因（多选）：涉及隐私 **100%**、涉及失败与遗憾 25%、不信任 AI 25%

多位作者回看旧文的共同情绪是"被生活磨平棱角""没达到当时设想的状态，心里有一点遗憾"。**回看旧文普遍伴随负面情绪——回访的语气必须承接遗憾，而不是套用"逆袭／成功"框架。**

### 2.3 核心张力：读者想要的价值，恰好落在作者最需要保护的区域

| 侧 | 想要什么 | 数据 |
| --- | --- | --- |
| **读者** | 看重大决定和判断的后续——辞职之后怎么样了、当年的预测应验了吗 | 反差／判断类勾选率 **17.3%**，是知识类的 **9 倍** |
| **作者** | 同样这类内容最敏感——涉及隐私、失败、遗憾 | **100%** 提到隐私；失败与遗憾被明确点出 |

因此「然后呢？」的成败不在于能不能问到，而在于**能不能让作者在安全的前提下愿意回答**。默认私有、可跳过、可修改、可撤回、公开需单独确认——**这些不是附加功能，而是需求得以成立的前提**。

### 2.4 调研边界（如实）

样本为便利样本、年龄集中于 18–24 岁，**不能外推**。作者侧仅 4 份，结论只用于定边界，不用于估计比例。项目工程已合格，但**"外部作者参与"这一条尚未验证**——线上还没有一条由真实外部作者确认发布的「后来」。

## 三、技术

### 3.1 系统结构

四层，职责边界写在 `docs/architecture.md` 与 `docs/contracts.md`：

| 层 | 负责 | 关键设计 |
| --- | --- | --- |
| 界面层 | 页面渲染、交互、状态、错误提示 | 前端不拍板任何权限判断 |
| 接口层 | 81 条 HTTP 路由，鉴权、幂等、去重、审计 | 统一 envelope：`request_id` + `status` + `data`／`error_code` |
| 智能层 | 识别抽取 / 动态采访 / 整理 / 校验四个 AI 任务 | 失败**永不**改变业务状态 |
| 数据层 | 来源、快照、同意、关注、会话、草稿、版本、通知…… | 历史与当下分开存储 |

**三条贯穿全局的工程原则：**

1. **业务状态 ≠ 执行状态。** 模型失败只会把采访会话切成 `mode: 'manual'`，**永远不会把案例改成"作者拒绝"**。
2. **前端按钮禁用不是安全边界。** 所有写接口在服务端重新检查归属与许可。
3. **发布走事务性 outbox。** 收件人在发布事务内冻结，投递时再次锁行复查——「撤回了还给读者推通知」在架构上不可能发生。

队列语义做到竞赛项目里少见的深度：`SKIP LOCKED` 防双领、`lease_expires_at` 崩溃回收、`fencing_token` 拒绝陈旧结果、退避重试、`dedupe_key` 偏唯一索引、心跳。

### 3.2 四个 AI 任务：全部真调模型，全部带防幻觉契约

| 任务 | 做什么 | 防幻觉机制 |
| --- | --- | --- |
| **A · 识别抽取** | 从原文里识别事件、计划、判断与时间锚点 | claim 文本**必须是原文子串**，refs 必须命中当前快照 |
| **B · 动态采访** | 基于原文提问，作者答什么下一问跟着变 | `basis_refs` 必须存在于本轮证据；重复提问、多问号拦截并一次性重试 |
| **C · 整理** | 把采访内容整理成结构化草稿 | `source_quote` 只能引已核对原文；`author_report` 只能引作者消息 |
| **D · 校验** | 检查草稿里有没有找不到出处的时间、数字、因果判断 | **规则先行，模型只能加严不能放宽** |

**最关键的一行代码**（`src/ai/evidence.ts:41`）——公开断言必须是逐字证据的子串，语义改写一律 blocking：

```ts
if (!s.text.trim() || !refs.some(e => e!.text.includes(s.text))) {
  add('unsupported_fact', 'Use an exact evidence excerpt or explicitly supply an author edit');
}
```

这一个判断同时拦住 AI 整理、拦住作者确认、拦住对外发布三层。**这是我们整个技术叙事里最愿意被追问的一段。**

## 四、知乎能力

> 这一章回答：**我们用了知乎的什么。**

### 4.1 调用的官方接口

| 能力 | 接口 | 用途 |
| --- | --- | --- |
| 官方搜索 | `GET /api/v1/content/zhihu_search` | 发现候选内容；返回标题、链接、摘要、作者名、编辑时间，**并附带精选评论** |
| OAuth 登录 | `openapi.zhihu.com/authorize` → `POST /access_token` → `GET /user` | **把站点账号与知乎身份绑定**——这是"本人"的唯一定义 |
| 本人创作列表 | `GET /api/v1/user/contents` | 作者导入自己的历史回答，同时写入归属核验证据 |
| 本人内容全文 | `GET /api/v1/user/content_detail` | 取得授权范围内的正文（含 URL 回校校验） |
| 本人内容评论 | `GET /api/v1/user/content_comments` | 按官方 ID 增量缓存评论 |

所有官方请求固定打到 `developer.zhihu.com`，路径强制 `/api/v1/` 前缀，`Bearer` + `X-Request-Timestamp` 鉴权，OAuth 场景追加 `X-OAuth-Token`，响应统一 `{Code, Data}` 信封并按错误码分流（含 429 限流）。**全站没有旁路，也没有爬虫兜底**（仓库无 puppeteer／cheerio 依赖）——拿不到就明确降级，不伪造。

### 4.2 三个只用知乎才能成立的地方

**① 输入空间被知乎 URL 命名空间封闭。**
系统的入口校验只承认 `zhihu.com/answer/{id}` 与 `zhuanlan.zhihu.com/p/{id}` 两种形态，其他一律拒绝；而这个 URL 还必须回官方搜索**按精确 URL 二次核对**才算导入成功。产品的起点对象在数据结构上就是知乎回答——**没有知乎 URL 就没有输入**。

**②「作者本人」这件事，只有知乎账号能证明。**
站点自己的账号证明不了任何事。只有 OAuth 拿到的 uid 能把站点用户与历史回答绑成一条归属证据，并以此解锁私密采访与模型处理同意。**摘要级候选一律标记 `ownership not established`**——这条区分是本项目与"任何社区都能做的 AI 采访玩具"的分水岭。

**③ 只有知乎有"十几年 + 稳定账号归属 + 时间纵深"的存量。**
发现引擎直接用官方搜索跑带**时间语义**的查询（辞职转行后来／考研经历后来／创业经历后来／搬家城市生活），返回的不是网页，而是**可回溯到作者账号的经历**。同一套机制换成通用搜索，命中的是文章，不是人和时间。

### 4.3 官方给了但我们没用的（如实）

`user/followees`（关注关系）、`user/favlists`／`user/collections`（收藏夹）**三个接口都没有调用**。本项目的「我的关注」是**站内自建的关注关系**，统计口径也是站内的，与知乎关注图谱没有数据往来。

这是当前最大的资产缺口，也是我们明确写在路线里的下一步：**关系链的接入属于需要平台协作的议题**，不写成本期已接入。

## 五、生态契合

> 这一章回答：**为什么必须长在知乎上**，以及**我们在这两条赛道上分别兑现了什么。**

### 5.1 为什么必须长在知乎上

一句话：**我们消费的不是"内容"，是"有人认领的、有时间纵深的人生经历"。**

- 换任何一个内容平台，起点不复存在——不是找不到相似的文本，而是**找不到"作者还在、账号可核验、且愿意为自己几年前的话负责"这件事**。
- 这个项目的核心动作是"回访原作者"。"原作者"这个概念只有在**账号与内容有稳定归属关系**的社区里才成立。
- 它不生产新内容，只提高存量内容的复用率——**对平台是成本最低的生态增益**。

知乎的 slogan 是"有问题，就会有答案"。「然后呢？」提供的是下一站：**不只是当时的答案，还有时间给出的答案。**

### 5.2 赛道一 · 灵魂匹配局（社区连接与兴趣社交）

官方口径：「从知友的兴趣、观点和内容行为出发，探索更自然的同好发现、讨论参与和关系建立……**让每一次连接都更有内容**——匹配的依据必须是内容。」

**我们兑现的是子方向 ①「内容驱动的兴趣匹配」。**

产品的核心动作「点击然后呢？」**本身就是一个由内容触发的显式兴趣信号**——不是填表交友，不是标签画像，而是"读完这一篇之后，我想知道这个人后来怎么样了"。而这个信号是可以被结构化的：

| 信号 | 说明 |
| --- | --- |
| 关注动作 | 一人一帖一票，取消后不计入统计 |
| 关注理由 | 点击时可选择"现在的结果与变化／过程中的转折与经历／回头看的感受与建议"，或填 20 字以内自定义疑问 |
| 理由汇总 | 经同意后由 AI 语义归类，形成"读者最想知道什么"的结构化视图，供作者在回访前看到 |

**这是一个诚实的、有内容的连接**：读者连接的不是一个"看起来相似的人"，而是**一段他真正读过的经历**；作者收到的不是"有人点了赞"，而是**一群人对这段经历的具体好奇点**。

子方向 ② 的兑现是弱一些的：自定义疑问的语义归类降低了"开口成本"，但它不是完整的"表达助手"。

**必须说清楚的边界**：本赛道常见的做法是"同好推荐、观点对齐／对撞、AI 分身代聊"。**我们不做好友推荐，也不做匹配算法。** 我们的适配点在"**内容 → 兴趣信号的产生与承接**"，以及由此建立的**读者↔作者长期关系**——而不是"找到和你相似的人"。

### 5.3 赛道二 · 知识炼金场（学习工具与知识生产）

官方口径：「让知乎内容不止于『读过』和『收藏过』，进一步转化为可以理解、使用和迁移的知识能力……**帮助用户建立理解，形成判断**。」

判分要点藏在最后那句：**产出不是摘要，是让用户变得更能思考。**

**我们兑现的是子方向 ①「内容 → 知识能力的转化」与子方向 ③「多 Agent 知识生产」。**

**关于"转化"**：一条旧回答在发布时是完整的，但时间把它变成了半截故事。读者读到的不是知识，是**一个没有结局的判断**。我们把"读完就走"变成"跟进到结局"，并且**把结局沉淀成结构化的经验记录**：

```
当时说了什么 · 后来发生了什么 · 时间跨度多长
判断是否应验 · 是否改变方向 · 是否愿意公开
```

这类数据的特殊性在于：**它必须建立在原作者自愿确认的基础上**——爬虫抓不到它，摘要生成不了它，问答模型也推不出它，因为答案只存在于作者本人手里，且只有在他愿意的时候才会出现。

累积之后，读者得到的不是"大家怎么看"，而是"**这样做的人后来怎么样了**"。这正是"建立理解、形成判断"——读者读到的是**和自己处境相似的人的真实走向**。

**关于"多 Agent 知识生产"**：四个 AI 任务分工协作完成一次知识生产——
`识别抽取`（从原文找可回访的事件与判断）→ `动态采访`（基于原文提问，随回答改变）→ `整理`（形成结构化草稿并标注材料类型）→ `校验`（检查有没有找不到出处的事实）。四个任务**全部真调模型**，且每一环都有可指证的防幻觉契约（见 §3.2）。

**一个必须强调的设计**：所有公开内容都标注**材料类型**——原文／接口摘要／作者回忆／AI 整理，四者视觉可辨且**不只靠颜色**。只有核对过的原文片段能加引号。**读者永远知道自己在读哪一种可信度的内容**——这是"知识"和"看起来像知识的东西"之间唯一靠得住的界线。

### 5.4 双赛道的共同点

两条赛道看起来分属"关系"与"知识"，但在这个产品里是同一件事的两面：

> **一条被读过的经历，几年后长出了结局——读者从中看到自己，平台从中得到结构化的经验资产。**

灵魂匹配局看到的是**连接的依据**（内容驱动的兴趣信号）；知识炼金场看到的是**连接的产物**（可迁移的经验结构）。两者共用同一条闭环，不需要两套系统。

### 5.5 与平台现有能力的关系

| 我们做 | 平台已有／我们不做 |
| --- | --- |
| 在原回答上挂一个"后续"对象 | 主站入口、站内分发——**属于后续合作议题，本期不写成已接入** |
| 站内关注与通知 | 知乎关注关系与推送权限——**本期使用站内自建关系，已如实标注** |
| 作者授权的阅读范围控制 | 主站账号体系——**通过 OAuth 绑定，不新建身份** |

`docs/PRD.md` 第 24 章已列出需要平台协作而非假定可用的能力清单：主站入口、作者账号匹配、通知偏好与触达权限、原回答关联后续对象、搜索／推荐分发、反骚扰与内容治理、用户撤回后的跨系统清理。**本期一项都没有写成"已接入"。**

## 六、社区价值

### 6.1 对四类人的价值

| 对象 | 得到什么 |
| --- | --- |
| **读者** | 从"看完一个故事"变成"跟进一个故事"。得到的是"和我处境相似的人后来怎么样了"——**做自己判断的参照**，而不是又一篇爽文 |
| **作者** | 低门槛地为当年的表达补上结局。不需要重写长文，AI 辅助提问，逐项确认，随时可撤回——**控制权始终在作者手里** |
| **内容生态** | 一次性的表达变成可持续更新的故事线，长尾内容重新获得生命周期 |
| **平台** | **在不生产新内容的前提下提高存量内容的复用率**——成本最低的生态增益 |

### 6.2 我们同时在保护什么

这个项目有一个不太寻常的地方：**它最大的产品约束，来自它最想服务的另一群人。**

调研发现读者最想看的是"重大决定和判断的后续"，而**恰好是这类内容，作者最敏感**——100% 提到隐私，失败与遗憾被明确点出。所以产品做了一系列看起来"反增长"的决定：

- **默认私有**，公开需单独确认
- **可跳过任何问题**，跳过即记下"这块不能公开"
- **可随时撤回**，撤回后公开入口立即失效
- **读者端一个字都看不到**作者的参与状态——没有"已催促 X 次""作者已应答"，因为那会变成对作者的社会压力
- **不做任何虚构的人气数字**——公开计数默认关闭

这些不是"合规成本"，而是**这个需求能够成立的前提**。作者不参与，产品就是空的。

### 6.3 边界与不承诺

- **不核实真相。** 平台核验的是身份，不是他说的对不对。公开页固定声明「作者自述，未由平台独立核实」
- **不做人生判决。** 作者说"还在进行中"，我们不写成最终结果；作者说"中途停了"，我们不追责、不嘲讽、不诱导认错
- **不假装。** 五问采访当前不稳定就是不稳定；线上还没有真实外部作者的「后来」就是还没有。**宁可显示"做不到"，也不假装做到了**

### 6.4 下一步

v1.0 之后拆成五个阶段，每个阶段只解决一个主问题：

```
阶段一 真实配对能跑通 → 阶段二 采访质量能对比 → 阶段三 低敏领域能安全开放
→ 阶段四 更多领域能开放 → 阶段五 经验结构能检索
```

**阶段一当前就能做**：分层招募读者与作者各 5–10 人，验证"真实读者关注真实作者"在自然场景下是否成立——目前所有规模扩张都建立在假设上。
